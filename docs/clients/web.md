# Web client (`apps/web/`)

The web app is Archie's main user interface: chat tabs for agent sessions, the orchestrator
("Archie") tab, realtime voice, settings, memory browser, and visualizations. It is one npm
package with **one source tree and two builds**:

| Build | Config | Output | Served at | Targets |
|---|---|---|---|---|
| main | `vite.config.main.ts` | `apps/web/dist/` | `/` | Chrome/Edge 109+, Firefox 115+, Safari/iOS 15.4+, Samsung 21+ |
| compat | `vite.config.compat.ts` | `apps/web/dist-compat/` | `/compat/` | Safari 12 / iOS 12 (the iPad mini 2) — legacy SystemJS chunks only |

Stack: React **18.3.1** on both builds (so both run the same runtime and the same tests),
Vite 8 + `@vitejs/plugin-react`, the compat build adds `@vitejs/plugin-legacy`, state in
**zustand 5** over a framework-free protocol module, plain CSS + CSS Modules with a Material 3
look whose colors, type and dimensions come from `apps/design-tokens/` (`dist/tokens.css`).
Markdown is `react-markdown` + `remark-gfm` on both builds, highlighting is `highlight.js` via
`lowlight`.

It replaced the old `frontend/` and `frontend-compat/` apps on 2026-10-05 (those now live in
`legacy/`, see [legacy-apps.md](legacy-apps.md)). The full design is
[spec 13 — web architecture](../specs/13-web-architecture.md); screens and
navigation are in [spec 11 — information architecture](../specs/11-information-architecture.md);
the wire protocol shared with Android is [spec 12 — client protocol](../specs/12-client-protocol.md).
This doc is the orientation map; the specs are the detail.

## Source layout

| Path | What it holds |
|---|---|
| `src/main.tsx` | Entry: compat polyfills → platform init → `createRoot(<App/>)` |
| `src/platform/` | Browser abstraction: `capabilities` (runtime feature detection; `?caps=compat` simulates the iPad in Chrome), `lowEnd`, `uuid` (randomUUID → getRandomValues → Math.random), `clipboard`, `media`, `storage` (try/catch localStorage), `emitter`, `time`, `remoteLog`, `debug` (`?debug=`, `window.__archie`), `polyfills.compat.ts` (ResizeObserver, focus-visible) |
| `src/protocol/` | Framework-free client core implementing spec 12: `wire/` (typed frames + tolerant decoder), `reducer/` (conversation reducer, tool results by id), `history/`, `resume/` (`(stream_id, seq)` checkpoints), `selectors/`. No React, no DOM types (`tsconfig.protocol.json`); runs the shared `apps/protocol-fixtures/` conformance suite |
| `src/services/` | REST client (`http/`), WebSocket + reconnect (`ws/`), per-session runtimes and the orchestrator runtime (`sessions/`), pool sync, uploads, capability probes (`capabilitiesProbe.ts`, e.g. "Show on TV") |
| `src/stores/` | zustand stores: `sessionStore` (one per open session), `sessionRegistry`, `tabs`, `catalog`, `serverConfig`, `prefs` (device prefs), `capabilities`, `connection`, `snackbar`, `liveStatus`, `scheduler` |
| `src/voice/` | Voice engine, no React: `core/VoiceController.ts` (signaling state machine), `transports/webrtc.ts` (OpenAI) and `transports/wsRelay.ts` (Qwen/Gemini over the backend), `audio/` (context, capture, PCM player, meters, cues), `recording/` |
| `src/features/` | Screens and feature UI: `conversation`, `composer`, `tools` (tool cards, "N steps" groups), `markdown`, `session-actions`, `session-settings`, `settings`, `auth`, `history`, `memory`, `visuals`, `voice` (VoiceDock, ActiveElsewhere) |
| `src/ui/` | Own M3 component kit: `primitives` (Stack/Inline/Cluster/ScrollArea…), `controls`, `overlays`, `navigation`, `a11y`, `icons` (generated by `npm run icons`) |
| `src/app/` | App shell, adaptive layout, navigation, tabs workspace, keyboard |
| `src/styles/` | reset, fonts, typography, primitives, media (`@custom-media` size classes), motion, theme |
| `src/test/` | Vitest setup, `regexpGuard.ts`, render and axe helpers |
| `src/dev/gallery/` | Component gallery (`#/dev/gallery`, `npm run build:gallery`) |
| `scripts/` | Build gates and generators: `scan-compat-bundle.mjs`, `check-budgets.mjs` + `budgets.json`, `check-token-vars.mjs`, `gen-icons.mjs`, `remote-console.js`, `vite-plugin-html-target.ts` |
| `mock-server/` | Fixture-replaying mock backend (port 8799) |
| `public-main/`, `public-compat/` | Static files per build (main has `manifest.json`, `sw.js`, `pcm-capture-worklet.js`; compat has none of these) |
| `vite.shared.ts` | Shared config: aliases, defines (`__TARGET__`, `__APP_VERSION__`, `__BUILD_TIME__`), PostCSS, dev proxy, ports |

Code branches on `__TARGET__` (`"main"`/`"compat"`) are dead-code-eliminated, so compat-only
code never reaches the main bundle. Compat-only modules use the `*.compat.ts` suffix.

## Development

From `apps/web/` (Node ≥ 22.12; builds run on the **laptop only** — the Jetson's glibc cannot
run this Node toolchain):

| Command | Does |
|---|---|
| `npm run dev` | Main dev server on **5450** |
| `npm run dev:compat` | Compat dev server on **5451** |
| `npm run mock` | Mock backend on **8799** (use with `ARCHIE_BACKEND=http://localhost:8799`) |
| `npm run preview` / `preview:compat` | Serve the built dists on the same ports |
| `npm run build` | `typecheck` → `gate:tokens` → `build:main` → `build:compat` → `gate:compat` → `gate:budgets` (both dists) |
| `npm run verify` | The full gate: `lint`, `lint:css`, `typecheck`, `test` (Vitest), `build` |
| `npm run build:preview` | Both builds with bases `/next/`, `/next-compat/` into `dist-preview/` (pre-cutover preview; those URLs now 307-redirect) |

- The dev server proxies `/api` (with WebSocket), `/memory`, `/uploads` and `/projects` to
  `ARCHIE_BACKEND` (default `http://localhost:8765`, `secure: false`, so the Jetson's
  `https://192.168.0.200` also works).
- Dev HTTPS uses `context/certs/` key + cert when present (needed for the microphone and WebRTC
  from LAN devices); `FN_HTTPS=0` forces HTTP.
- **`gate:tokens` runs `npm --prefix ../design-tokens run check`**, so `apps/design-tokens`
  needs its own `npm install` once (the installers do it). Without it `npm run build` fails at
  that step, before any bundle is produced.
- Vitest projects: `protocol` (node), `dom` (jsdom), `compat` (jsdom + compat aliases + the
  RegExp guard), `scripts` (gate tests).

## The compat build (Safari 12 / iOS 12)

`vite.config.compat.ts`: base `/compat/`, `@vitejs/plugin-legacy` with targets
`safari >= 12, ios_saf >= 12`, `renderModernChunks: false`, `polyfills: true` (usage-based
core-js), terser, `cssTarget: ['safari12', 'ios12']`, hidden sourcemaps. With legacy-only
chunks Vite emits no `.css` file — each chunk's CSS is inlined in the JS.

The Safari 12 rules are enforced by tools, not memory:

- **Compat bundle scanner** (`scripts/scan-compat-bundle.mjs`, run by `gate:compat`): parses
  every compat JS file with acorn at **ES2019** (ES2020+ syntax fails), validates every regex
  literal and string-literal `RegExp(...)` argument and fails on **lookbehind, named groups,
  named back-references, and the `d`/`v` flags**; flags suspicious regex-looking strings; and
  checks the CSS for `gap`, `inset`, logical properties, `:is/:where/:has`, raw
  `:focus-visible`, `dvh`, `color-mix`, `clamp`, `@layer`, `@container`. Exceptions go in
  `scripts/compat-scan-allowlist.json` (one entry today: core-js's own named-group feature
  probe inside a try/catch). Stale allowlist entries fail the gate.
- **RegExp guard** (`src/test/regexpGuard.ts`) wraps the global `RegExp` in the `compat` test
  project, catching regexes built at runtime (e.g. by highlight.js grammars).
- ESLint `es-x` + `compat` rules and Stylelint bans give feedback before a build.

### Safari 12 pitfalls that still apply

| Pitfall | Rule in this codebase |
|---|---|
| A regex literal with lookbehind `(?<=`/`(?<!` or a named group `(?<name>` is a **parse-time SyntaxError** on Safari 12: the whole chunk dies and the iPad shows a white screen | The scanner gate. `mdast-util-gfm-autolink-literal` is aliased on both builds to a lookbehind-free fork (`src/features/markdown/gfm/autolinkLiteralSafe.ts`); Prism/`react-syntax-highlighter`/`marked`/Shiki are not used; compat ships a curated highlight.js language set (`languages.compat.ts`) |
| Flex `gap` needs Safari 14.1 | `gap`/`row-gap`/`column-gap` are banned everywhere (only `grid-gap` allowed). Spacing goes through the `Stack`/`Inline`/`Cluster` primitives (`> * + *` margins) |
| `> * + *` never matches **text nodes**, so `<svg/> label` gets no spacing | The `Inline` and `Cluster` components wrap every string/number child in a `<span>`; icon+label components use an explicit icon margin |
| `inset`, logical properties, `aspect-ratio` unsupported | `postcss-preset-env` lowers them per build; the scanner re-checks the output |
| No Pointer Events (Safari 13+), no `ResizeObserver` (13.1+), `matchMedia().addEventListener` (14+), no `crypto.randomUUID` (also missing on any plain-HTTP origin), no `visualViewport`, no `prefers-color-scheme` (iOS 13) | Mouse + touch gestures; ResizeObserver polyfill; `addListener`; `platform/uuid.ts`; "System" theme falls back to dark |
| iOS zooms into inputs smaller than 16 px | Only the kit's `TextField`/`Select`/`Composer`/`SearchField` render inputs, always at 16 px |
| Momentum scrolling and programmatic scroll fight each other | Every scroll container is the `ScrollArea` primitive (`-webkit-overflow-scrolling: touch`, deferred programmatic scrolls) |
| No `AudioWorklet` / `MediaRecorder` on iOS 12 | Features chosen by runtime capability detection: ScriptProcessor capture fallback, WAV fallback for audio messages, unsupported voice controls hidden with a reason |
| iPad Safari pins an old bundle | The backend serves `index.html` with no-cache headers; after a deploy a reload is enough |

## Harness settings (model + options per harness)

Settings → Agent sessions and the session settings sheet (⋮ → Session settings) render every
harness's configuration from its catalog, `GET /api/config/harnesses` (spec 12 §8.1): the model
picker and each option (reasoning effort, thinking, thinking budget, …) by kind — `select`,
`toggle` and `number` all become a Select with "CLI default" plus the values (a number adds a
value field, the model a "Custom model id…" field). Nothing is hard-coded per harness: a new
harness or option only changes the backend catalog.

- **Global page**: the default harness's block ("<Harness> defaults") plus collapsible blocks for
  the other harnesses. Each control saves at once: `{harness_model: {p: id}}` /
  `{harness_options: {p: {key: value | null}}}` (null = CLI default). Catalog `warnings` show as a
  notice; "Refresh models" refetches with `?refresh=true`.
- **Session sheet**: the "Harness" stack — harness, model, options — each with a
  "Default (…)" row that inherits the global value; changing the harness resets the model and
  options to inherit (they belong to one harness). `harness_options` is sent as a whole map
  (absent key = inherit, `null` = CLI default, empty = `null`).
- **Gating** (`src/features/settings/harness.ts`, unit-tested): options and choices restricted by
  `models`, effort narrowed to the model's `efforts` (`[]` hides it), `supports_thinking: false`
  hides `thinking`/`thinking_*`; an unknown model (CLI default, custom id) shows everything.
- Older servers without the endpoint: the store builds the same rows from
  `/api/config/providers` + `/api/config/harness/qwen/models` (`src/services/harnessFallback.ts`).
- Components: `HarnessFields.tsx`; sample catalogs for the gallery/tests in `harnessSamples.ts`
  (same data as `mock-server/data/harnesses.json`).

## Low-end mode

`src/platform/lowEnd.ts` adds `html.low-end` when `navigator.hardwareConcurrency <= 2` or
`navigator.deviceMemory <= 1` (the iPad mini 2 reports 2 cores), **always on the compat
build**, and whenever the device pref "Reduce motion" is set. Effects: no CSS animations or
transitions (also under `prefers-reduced-motion`), no backdrop blur, stream flushes to React
every 100 ms instead of every frame, 80 instead of 200 mounted messages per panel, deferred
highlighting skipped for blocks over 8 KB, 10 fps meters. Details: spec 13 §2.7.

## Remote console logging

Devices without DevTools (the iPad) report their console to the backend:

- `scripts/remote-console.js` is a hand-written ES5 script inlined into `index.html` by
  `vite-plugin-html-target.ts`. It mirrors `console.*` and always sends window `error` and
  `unhandledrejection` events, via `navigator.sendBeacon` to **`POST /api/debug/log`**. Limits:
  60 messages per 10 s (then one "dropped N" line), 4 KB per message. Compat lines carry a
  `[compat]` prefix.
- Console mirroring is **on by default on compat, off on main**; the device pref
  Settings → This device → Remote logging (`src/platform/remoteLog.ts`, localStorage key
  `archie.remoteConsole`) overrides it per device.
- The backend handler (`backend/api/routes/debug.py`) appends to **`logs/remote_console.log`**;
  `GET /api/debug/log` returns the file.

```bash
tail -f logs/remote_console.log            # watch live (on the machine serving the page)
curl -s http://localhost:8765/api/debug/log | tail -20
```

On a blank iPad screen: look for `[UNCAUGHT] [compat] SyntaxError: Invalid regular expression`
— a dependency slipped a lookbehind or named group past the gate (or a dynamic `RegExp` the
scanner only warned about).

## Deploy

The Jetson has no Node, so the dists are built on the laptop and rsynced (each with `--delete`)
to the same paths under `~/assistant/` on the Jetson. The procedure is in
[deployment.md](../infrastructure/deployment.md) and the `/server-management` skill
(`context/skills/server-management/SKILL.md`).

**Rule: always deploy `apps/web/dist/` and `apps/web/dist-compat/` together.** One
`npm run build` produces both; shipping only one leaves the other client environment stale.
No backend restart is needed (static files, no-cache `index.html`); clients hard-reload.

**Symptom to recognise:** "voice (or any new feature) fails from the web but works from the
Android app" against the same backend usually means a **stale web dist on the Jetson**, not a
backend bug — the native app ships its own code, the web build only changes when someone
rebuilds and rsyncs. Check the deployed `dist/index.html` mtime against the newest `src/`
change and grep the deployed `dist/assets/*.js` for a string only the latest code contains.
Fix: rebuild on the laptop, rsync both dists.

Code reaches the Jetson through git first (so `apps/web/` exists there before the rsync);
context-sync never carries dists.

## Backend routes

`backend/api/app.py` `_spa_dirs()` plus the root catch-all: `/` → `apps/web/dist`,
`/compat/` → `apps/web/dist-compat`, `/legacy/` and `/legacy_compat/` → the legacy dists,
`/next/` and `/next-compat/` → 307 to `/` and `/compat/`. Each prefix is registered only when
its build exists. Tests: `backend/tests/test_spa_routes.py`. Files under `context/public/` are
served at the URL root by the same app (see
[visualizations-and-sharing.md](../integrations/visualizations-and-sharing.md)).
