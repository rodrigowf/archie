# Claude Code harness — install this if you want to run sessions backed
# by the bundled `claude` CLI.  Skip it for a Qwen-only deployment.
#
# Loaded lazily by manager/__init__.py via PEP 562, so installing this
# does NOT change what's imported at backend startup — the SDK is only
# loaded the first time a Claude session is created.

# EXACT pin, bumped deliberately (2026-10-07: 0.1.81 → 0.2.164, bundled
# CLI 2.1.139 → 2.1.292).  Every SDK release swaps the bundled `claude`
# binary, and CLI behaviour changes without SDK changelog entries, so a
# range pin lets a reinstall silently change what sessions do.
#
# What 0.2.x changed for us (Python API: additions only, nothing we use was
# removed; details in docs/harnesses/claude-code.md "SDK version"):
#   * CLI >= 2.1.287 streams thinking as empty "updates" unless the host asks
#     for a display -> session.py always sends --thinking-display summarized
#     and drops empty thinking deltas/blocks.
#   * CLI >= 2.1.233 hides TodoWrite/Task* on 4.8 / 5.x models -> we set
#     CLAUDE_CODE_ENABLE_TODO_TOOLS=1 (harness option `todo_tools`).
#   * CLI 2.1.274 stopped waiting for deferred MCP servers on turn 1 -> we
#     set CLAUDE_CODE_MCP_STARTUP_WAIT_MS=2000 (the old bound).
#   * New ConversationResetMessage on /clear -> session id re-captured.
#   * The default model (no --model) is now Sonnet 5.5 on a subscription.
# 0.2.x also keeps the 0.1.51/0.1.40 fixes that let us drop two
# monkey-patches (no anyio TaskGroup in Query; unknown message types are
# skipped), and adds zombie-CLI prevention on cancel (0.2.111).
#
# Verify after any (re)install or bump:
#   .venv/bin/python -c "import claude_agent_sdk as s, claude_agent_sdk._cli_version as v; print(s.__version__, v.__cli_version__)"
#   -> 0.2.164 2.1.292 ; then run the Claude tests + the smoke list in
#   docs/harnesses/claude-code.md.  On aarch64 hosts (Jetson) also run the
#   bundled binary once before restarting the backend:
#   <venv>/lib/python3.*/site-packages/claude_agent_sdk/_bundled/claude --version
# Rollback: pip install 'claude-agent-sdk==0.1.81' + restart (JSONLs stay
# compatible both ways).
#
# The pin is load-bearing, and a venv can silently drift from it: on
# 2026-08-25 the installed SDK was 0.1.39, two fixes short of the old floor.
# The bundled CLI (2.1.240) emits `rate_limit_event` as a session nears a
# usage limit; 0.1.39 has no case for it, so parse_message raised
# MessageParseError, killed _receive_loop, and the reaper closed the
# session as subprocess_crashed.  If sessions start dying with
# "Unknown message type" or behave differently after a deploy, check the
# *installed* version first (command above).
claude-agent-sdk==0.2.164
